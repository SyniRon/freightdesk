# Custom service for uncovered routes

When a user picks a route no catalog service covers (a custom destination, or an unconfigured pair), the picker would dead-end: no card, so the manual per-m³ rate had nowhere to render and the route couldn't be priced. We resolve this with a **synthetic `Service`** generated at runtime from user input — a per-m³ rate plus optional collateral-%, building a real `RouteFormula` that flows through the existing `evaluateServices`/copy-block pipeline — rather than painting a manual price onto the dimmed catalog couriers that declined the route (the rejected alternative).

**Why not the cheaper option (dimmed couriers + phantom quote):** A courier card that simultaneously declines a route and shows a price for it is incoherent, and the global rate override has no natural owner on a route no courier serves. The synthetic service gives the rate a real owner and keeps the eligibility model honest (a card means "this entity will carry it").

**Scope of the synthetic service:** no caps, no `minReward` (no shipper imposes them) → always `eligible`, never `splittable`. Its rate is card-local, persisted under its own `localStorage` key, independent of the global catalog-displacement rate override (which is inert when no route matches). An optional **recipient** (the contract assignee / Shipper string) is selectable from catalog corp names or free-typed, and may be left empty for a public contract — the catalog-name seeding exists to bridge **catalog lag** (a known shipper serves a route in-game before its YAML is updated).

**Triggers only on the no-route-matched case**, not on cargo-too-large (a rate can't fix a physical cap, so that empty state is unchanged). Independent of #28 (predicate/region matching), which only changes how often the trigger fires, never how the no-match outcome is handled. The custom-card conversion count, fired with a redacted route (`service: "custom"`, no user-typed destination/recipient string — see ADR 0007), doubles as a demand signal for which services to add next.
